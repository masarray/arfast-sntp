## Do not regress

`MultiPeerWorker` remains the single bounded NTP supervisor, with up to four concurrent probes, fresh validated Mode 4 replies, conservative source selection and NTP RATE/DENY/RSTR protection. Sources OFF means no UDP NTP polls and no Windows time adjustment while the Service and its local IPC remain available. Adapter changes and manual Windows clock jumps invalidate stale observations. Successful clock adjustments require post-step new NTP samples.

The GUI is Avalonia Studio; the worker owns clock correction. Inno publishes only one canonical Windows installer `ARFastSNTP-Setup-Windows-x64.exe` and its `.sha256` sidecar. Never overwrite a previously published tag or binary.

## Release and review discipline

1. Verify `main` SHA and the newest CI result before coding. Branch → PR → review → merge; use expected SHA to avoid stale-base merges.
2. Make engine changes only when explicitly requested, with Windows regression CI and real test artifacts. Never use live SCADA/SOE/historian hosts to alter the system clock.
3. Keep current stable tag intact; increment the Inno and .NET versions only for a new publicly released binary.
4. Website changes should use **real** screenshot assets, keep `releases/latest/download` links, and pass site/link validation. A docs-only merge may start Pages deployment without a new binary release.
5. Pending signing, long soak, full rollback and industrial certification remain tracked in [Issue #2](https://github.com/masarray/arfast-sntp/issues/2).
